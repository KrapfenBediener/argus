# Plan 04-01: Edge Function `exchange-code`

**Phase:** 4 — Serverseitige Absicherung  
**Wave:** 1 (keine Abhängigkeiten, kann sofort starten)

## Objective

Eine Supabase Edge Function deployen, die einen 8-stelligen Code validiert und
ein signiertes JWT zurückgibt. Dieses JWT enthält `praesidium_id`, `is_master`
und `exp` — aber keinen Klarnamen, keine E-Mail, keine UID.
Die App ruft diese Function statt der direkten DB-Abfrage auf.

## Context

- SUPA_URL: `https://sehuosjyjmrpzcqrelej.supabase.co`
- SUPA_KEY (anon): in `index.html:100`
- PAT (Management API): `${SUPABASE_PAT}`
- Supabase Ref: `sehuosjyjmrpzcqrelej`
- Edge Functions laufen auf Deno, werden über die Management API deployt
- JWT muss mit `SUPABASE_JWT_SECRET` signiert sein damit PostgREST es verifiziert

<action>
Datei `supabase/functions/exchange-code/index.ts` anlegen (Verzeichnis ggf. erstellen).

Die Function:
1. Empfängt POST mit `{ code: "XXXX-YYYY" }` (JSON body)
2. Bereinigt den Code: Bindestriche + Leerzeichen entfernen, uppercase → `cleanCode`
3. Sucht in `access_tokens`: `short_code = cleanCode[0:4]+'-'+cleanCode[4:8]`
   - Felder: `token, praesidium_id, is_master, label, short_code, temporary, ttl_hours, single_use, used_at`
   - Supabase-Client mit `SUPABASE_SERVICE_ROLE_KEY` (nicht anon!) für privilegierten Zugriff
4. Prüft: row vorhanden? / `single_use && used_at` → 401 "Ungültiger oder verbrauchter Code"
5. Berechnet TTL: `ttl_hours` wenn gesetzt, sonst 30 Tage (2592000 s); is_master immer 30 Tage
6. Signiert JWT (HMAC-SHA256 mit `SUPABASE_JWT_SECRET`):
   ```
   { iss: "supabase", sub: "argus-device", role: "anon",
     praesidium_id: row.praesidium_id,
     is_master: row.is_master,
     iat: now_unix, exp: now_unix + ttl_seconds }
   ```
7. Wenn `single_use && !used_at`: UPDATE `used_at = now()` (service role key)
8. Lädt Präsidiumsname: SELECT name FROM praesidien WHERE id = praesidium_id
9. Gibt zurück: `{ jwt, exp, praesidium_id, praesidium_name, is_master, ttl_seconds }`
10. CORS-Header setzen: `Access-Control-Allow-Origin: *` für OPTIONS-Requests

Deno JWT-Signing (kein npm, nur Deno-Standard):
```typescript
const key = await crypto.subtle.importKey(
  "raw", new TextEncoder().encode(jwtSecret),
  { name: "HMAC", hash: "SHA-256" }, false, ["sign"]
)
// Header: base64url({alg:"HS256",typ:"JWT"})
// Payload: base64url(JSON.stringify(payload))
// Signature: base64url(HMAC-SHA256(header+'.'+payload, key))
```

Fehler-Responses: `{ error: "..." }` mit passendem HTTP-Status (400/401/500).
</action>

<task id="04-01-T2" name="Edge Function über Management API deployen">

<read_first>

<action>
Edge Function deployen via Supabase Management API:

```bash
PAT="${SUPABASE_PAT}"
REF="sehuosjyjmrpzcqrelej"

# Function-Code als Multipart hochladen
curl -X POST "https://api.supabase.com/v1/projects/$REF/functions" \
  -H "Authorization: Bearer $PAT" \
  -F "metadata={\"name\":\"exchange-code\",\"verify_jwt\":false}" \
  -F "file=@supabase/functions/exchange-code/index.ts;type=application/typescript"
```

`verify_jwt: false` weil die Function den JWT AUSSTELLT (nicht empfängt).

Anschliessend prüfen ob die Function deployed ist:
```bash
curl -s "https://api.supabase.com/v1/projects/$REF/functions/exchange-code" \
  -H "Authorization: Bearer $PAT"
```
Erwartetes Feld: `"status": "ACTIVE"` (kann 30–60 s dauern).
</action>

<acceptance_criteria>
