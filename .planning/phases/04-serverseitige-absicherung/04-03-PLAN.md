# Plan 04-03: RLS-Policies schärfen + E2E-Verifikation

**Phase:** 4 — Serverseitige Absicherung  
**Wave:** 3 (nach 04-02 — App muss JWT senden bevor RLS anon-Key blockiert)

## Objective

Die Supabase-Datenbank kennt jetzt das JWT-Präsidium jeder Anfrage und erzwingt
Datentrennung auf Server-Ebene. Alter Anon-Key ohne JWT liefert 0 Zeilen.
Die Phase ist damit vollständig — echter Schutz, nicht nur App-seitige Filterung.

## Context

- Supabase Ref: `sehuosjyjmrpzcqrelej`
- PAT: `${SUPABASE_PAT}`
- Aktuelle Policies: `anon_all` mit `qual: true` auf allen Tabellen (alles offen)
- JWT-Claim-Zugriff in PostgREST: `current_setting('request.jwt.claims', true)::json`
- Betroffene Tabellen: `patients`, `ccps`, `checklists`, `access_tokens`, `praesidien`
- `praesidien` muss auch ohne JWT lesbar bleiben (für den Freischalt-Screen)

<task id="04-03-T1" name="JWT-Hilfsfunktionen in der Datenbank anlegen">

<read_first>
- `.planning/phases/04-serverseitige-absicherung/04-CONTEXT.md` — RLS-Granularität Präsidiums-Ebene
</read_first>

<action>
Zwei stabile SQL-Hilfsfunktionen anlegen via Management API (POST /database/query):

```sql
-- Extrahiert praesidium_id aus dem JWT-Claim
create or replace function public.argus_praesidium_id()
returns uuid language sql stable security definer as $$
  select nullif(
    current_setting('request.jwt.claims', true)::json->>'praesidium_id',
    ''
  )::uuid
$$;

-- Prüft ob der JWT-Inhaber MasterToken-Rechte hat
create or replace function public.argus_is_master()
returns boolean language sql stable security definer as $$
  select coalesce(
    (current_setting('request.jwt.claims', true)::json->>'is_master')::boolean,
    false
  )
$$;
```

`security definer` damit die Funktionen mit den nötigen Rechten laufen.
`stable` signalisiert PostgreSQL, dass die Funktionen innerhalb einer Transaktion
dasselbe Ergebnis liefern (erlaubt Indexnutzung).

Verifikation:
```sql
select public.argus_praesidium_id();  -- muss NULL zurückgeben (kein JWT im SQL-Editor)
select public.argus_is_master();       -- muss false zurückgeben
```
</action>

<acceptance_criteria>
- `public.argus_praesidium_id()` existiert in der DB
- `public.argus_is_master()` existiert in der DB
- Beide Funktionen liefern NULL/false wenn kein JWT-Claim gesetzt
- `information_schema.routines` zeigt beide Funktionen unter `public` schema
</acceptance_criteria>

</task>

<task id="04-03-T2" name="RLS-Policies für patients, ccps, checklists ersetzen">

<read_first>
- `.planning/phases/04-serverseitige-absicherung/04-CONTEXT.md` — Präsidiums-Ebene, MasterToken sieht alles
</read_first>

<action>
Alle drei Tabellen in einer SQL-Migration:

```sql
-- ── patients ──────────────────────────────────────────
drop policy if exists anon_all on public.patients;

create policy "argus_patients_rw" on public.patients
  for all to anon
  using (
    public.argus_is_master()
    or ccp_id in (
      select id from public.ccps
      where praesidium_id = public.argus_praesidium_id()
    )
  )
  with check (
    public.argus_is_master()
    or ccp_id in (
      select id from public.ccps
      where praesidium_id = public.argus_praesidium_id()
    )
  );

-- ── ccps ──────────────────────────────────────────────
drop policy if exists anon_all on public.ccps;

create policy "argus_ccps_rw" on public.ccps
  for all to anon
  using (
    public.argus_is_master()
    or praesidium_id = public.argus_praesidium_id()
  )
  with check (
    public.argus_is_master()
    or praesidium_id = public.argus_praesidium_id()
  );

-- ── checklists ────────────────────────────────────────
drop policy if exists anon_all on public.checklists;

create policy "argus_checklists_rw" on public.checklists
  for all to anon
  using (
    public.argus_is_master()
    or ccp_id in (
      select id from public.ccps
      where praesidium_id = public.argus_praesidium_id()
    )
  )
  with check (
    public.argus_is_master()
    or ccp_id in (
      select id from public.ccps
      where praesidium_id = public.argus_praesidium_id()
    )
  );
```
</action>

<acceptance_criteria>
- `pg_policies` zeigt `argus_patients_rw`, `argus_ccps_rw`, `argus_checklists_rw`
- Alte `anon_all`-Policies auf diesen Tabellen nicht mehr vorhanden
- `select count(*) from public.patients` mit Anon-Key (ohne JWT) gibt 0 zurück
- `select count(*) from public.ccps` mit Anon-Key gibt 0 zurück
</acceptance_criteria>

</task>

--   anon_read (SELECT, qual: true) — für validateInviteToken-Fallback
