## Vertrag der Plugin-API (JS ↔ Swift; Plan 04 programmiert dagegen, Plan 01 kennt `MESH_PROTO.jsName`)
Methoden (alle `CAPPluginReturnPromise`, lösen sofort auf — nie blockierend):
- `start({ccpId, secret, deviceNo, hub})` — `secret` = `ccps.join_token` (32 hex); `displayName` wird in Swift gebildet: `"argus-<ccpHash>-<deviceNo>"` (pseudonym, kein Bedienerkürzel). Antwort `{ccpHash}`.
- `stop()` — Advertiser/Browser stoppen, alle Sitzungen trennen; Peer-ID bleibt archiviert.
- `setRole({hub, full})` — Rolle Nabe/Speiche und „Stern voll“; startet den Advertiser mit neuem `discoveryInfo` neu, falls geändert.
- `connect({to})` — Speiche lädt die Nabe (`to` = peerKey) mit HMAC-Kontext ein, Timeout 15 s. (JS entscheidet per `meshNext`, wen; Swift lädt nie von selbst ein.)
- `send({to, json})` — `to` = peerKey oder `"all"`; UTF-8 JSON als Frame Art 0, `.reliable`; fire-and-forget.
- `sendResource({to, name, base64})` — Bytes (nicht Data-URI) als temporäre Datei per `sendResource(at:withName:toPeer:)`; Datei nach Abschluss gelöscht.
- `setKeepAwake({on})` — `UIApplication.shared.isIdleTimerDisabled` (Owner-Frage 5; Standard: ja, solange Mesh aktiv UND kein Netz).
- `status()` — `{hub, full, ccpHash, dev, spokes, connected, peers:[…]}`.
Events (`notifyListeners`):
- `peers` → `{peers:[{key, dev, ccp, full, state}]}` mit `state ∈ found|connecting|connected|lost`; `connected` erst nach beidseitig bestandener Challenge.
- `message` → `{from, json}` (nur von `connected` Peers).
- `resource` → `{from, name, base64}` (nur von `connected` Peers).
- `state` → `{s: idle|running|background|denied|error, detail}`.
peerKey = `MCPeerID.displayName` (`argus-<ccpHash>-<dev>`); `dev` wird aus `discoveryInfo["dev"]` gelesen.

## Beitrittsbeweis (MeshProof, CryptoKit) — Vektor in tests/fixtures/mesh-vectors.json → join
- `ccpHash(ccpId)` = erste 8 Hex-Zeichen von SHA256(UTF8(ccpId)).
- `key(secretHex)` = `SymmetricKey(data: Bytes(secretHex))` (16 Bytes aus 32 hex; bei ungültigem Hex: UTF8-Bytes des Strings als Fallback).
- `proof(key, ccpHash, dev, nonce)` = HMAC-SHA256(key, UTF8(`"<ccpHash>|<dev>|"`) ‖ nonce) — 32 Bytes.
- Einladungs-Kontext = `dev` (1 Byte) ‖ nonce (16 Bytes) ‖ mac (32 Bytes) ‖ ccpHash (8 ASCII) = 57 Bytes; `verifyContext(ctx, key, ccpHash)` prüft Länge, Hash-Gleichheit und MAC (`isValidAuthenticationCode`).
- Transport-Frames (erstes Byte): `0` = JSON (UTF-8), `1` = Auth-Nonce (16 Bytes, wird nach `.connected` von BEIDEN Seiten gesendet), `2` = Auth-Beweis (`dev` 1 Byte ‖ mac 32 Bytes über die EMPFANGENE Nonce). Erst wenn ein Peer meinen Beweis-Frame korrekt beantwortet hat, gilt er als `connected`; vorher werden Art-0-Frames und Ressourcen verworfen. Ohne gültigen Beweis innerhalb `5 s` nach `.connected` → `session.disconnect()`.

## Discovery (statischer Diensttyp — Pitfall 2)
- `serviceType = "argus-ccp"`; Info.plist `NSBonjourServices` = `_argus-ccp._tcp`, `_argus-ccp._udp`; `NSLocalNetworkUsageDescription` deutsch (Text in RESEARCH „Info.plist“).
- `discoveryInfo = ["ccp": ccpHash, "dev": "<n>", "v": "1", "full": "0"|"1"]` (< 400 Bytes). Browser meldet nur Peers mit passendem `ccp` und `v`.
- Peer-ID archiviert (`NSKeyedArchiver`, `requiringSecureCoding: true`) unter UserDefaults-Schlüssel `argus_peer_<ccpId>_<dev>` (+ `_name`), neu nur bei Namenswechsel — Ghost-Peer-Schutz (Pitfall 3).
- `didNotStartBrowsingForPeers`/`didNotStartAdvertisingPeer`: Fehler mit Code `-65570` (kDNSServiceErr_PolicyDenied) oder `NSNetServicesErrorDomain` → `state:"denied"`, sonst `state:"error"` mit `detail` = `localizedDescription` (nie Patientendaten im Log).

## Lebenszyklus
- `UIApplication.didEnterBackgroundNotification` → `transport.stop()` + `state:"background"` (MC trennt ohnehin; so weiß JS es sofort). Vordergrund: JS ruft `start()` erneut (Plan 04, `visibilitychange`).
- Alle Delegate-Callbacks auf `DispatchQueue.main` an das Plugin melden (MC ruft auf Hintergrund-Queues).
