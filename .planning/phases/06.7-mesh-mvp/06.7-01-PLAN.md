## Regeln für alle neuen Funktionen (Vertrag, gilt auch für Plan 04)
- Reine Funktionen ohne Globals, außer den ausdrücklich erlaubten: `FGROUPS`, `MESH_GROUPS_ORDER`, `MESH_PROTO`, `mergeGroups`, `groupSig`, `groupSigs`, `clearPending`, `devStatus`. Tests laden sie gemeinsam per `evalFunctions(script, [...], ['FGROUPS','MESH_GROUPS_ORDER','MESH_PROTO'])`.
- Hilfsfunktionen liegen INNERHALB der Vertragsfunktion (`_extract.cjs`-Regel, siehe Kopf von `tests/sync.test.cjs`).
- Keine Eingabe wird verändert, außer dokumentiert (`meshReceipt`, `meshLockApply`, `meshPhotoAccept` verändern `p` wie `clearPending`/`tombstoneMark`).
- Konstanten des Nachrichtenschemas stehen in `MESH_PROTO` (ein Objektliteral, extrahierbar).

## Nachrichtenschema (RESEARCH „Nachrichtenschema“; Umschlag + Typen)
Jede Nachricht: `{v:1, id:"<from>-<seq>", t, from:<Gerätenummer 1..99>, ccp:"<8 hex SHA256(ccpId)>", at:<nowMs Sender>, …}`.
Typen (`MESH_PROTO.types`): `hello` (op, mm, app, online — KEINE Krypto, Authentisierung erledigt der Transport in Plan 02), `inv` (order, pats:{id:[8 Stempel, fotoFlag]}), `req` (pats:{id:[gruppen]}), `delta` (part, of, pats:[Delta-Objekte]), `rcpt` (pats:[{id, upTo}]), `foto-req` (pid, to), `lock` (pid, by, lockedAt, release, mm), `meta` (hub, mm, full, devs:[{dev, op, last, open, online}]), `hb` (op, open, online, offQ).

## Vertrag der Funktionen (Signaturen + Semantik; Tests prüfen genau das)
- `var MESH_GROUPS_ORDER = ['cat','st','vit','tx','tq','stamm','foto','del']` — 7 Inhaltsgruppen aus `FGROUPS` in fester Reihenfolge + `del` (Grabstein).
- `var MESH_PROTO = {v:1, jsName:'ArgusMesh', service:'argus-ccp', types:[…9 Typen…], maxMsg:65536, chunk:24576, hbMs:15000, invMs:30000, deltaDebounceMs:500, rcptBundleMs:5000, hubLostMs:10000, inviteTimeoutMs:15000, settleMs:5000, fullRetryMs:30000, helloMs:5000, futureMs:60000, maxSpokes:7, seenMax:2000}`.
- `meshInventory(list, order)` → `{[id]: [s_cat, s_st, s_vit, s_tx, s_tq, s_stamm, s_foto, s_del, fotoFlag]}`. Überspringt `demo`/`training`. Stempel je Gruppe = `p.fts[g].t`, sonst für `del`: `p.deletedAt ? (p.updated||0) : 0`, sonst `p.updated||0`. `fotoFlag` = `p.photo ? 1 : 0`. Hilfsfunktion `stamp(p,g)` innen.
- `meshDiff(mine, theirs, order)` → `{[id]: [gruppen]}` = was ICH von DIR brauche: unbekannte ID → alle Gruppen in `order` (inkl. `foto`, damit Flag + Stempel kommen — nie Bytes); bekannte ID → nur Gruppen mit `theirs[i] > mine[i]` (auch `foto`, Vergleich der Stempel; das Foto selbst kommt nie über `inv/req/delta`, D6.7-06).
- `meshDelta(p, groups, FG)` → Kopie nur der angeforderten Gruppen: immer `id, num, ccp, ccpId, created, by, updated, fts:{}`; je Gruppe `g`: `del` → `deletedAt/deletedBy/deletedDev`; `foto` → `hasPhoto:!!p.photo` (nie `photo`); sonst alle Schlüssel `FG[g]`, die in `p` definiert sind; `fts[g]={t,d,b}` ohne `p`; `conf` nur wenn vorhanden. Nie Schlüssel mit `_`-Präfix, nie `photo`, `lockedBy`, `lockedAt`.
- `meshApply(local, incoming, FG)` → `{merged, changed, isNew, needPhoto}`. Ohne `local`: `merged` = tiefe Kopie von `incoming`, `isNew:true`, `changed:true`. Sonst `merged = mergeGroups(local, incoming, FG)` (Globals `mergeGroups`/`groupSig`). Danach: `hasPhoto` aus `merged` entfernen; fehlt `incoming.photo` → `merged.photo = local.photo || ''` (fotoloses Delta löscht nie ein Foto); `merged._fotoRemote = (incoming.hasPhoto===true) && (!merged.photo || fotoNeuer)`, wobei `fotoNeuer` = `incoming.fts.foto.t > (local.fts.foto.t||0)`; `incoming.hasPhoto===false` → `_fotoRemote` löschen. `changed` = eine Gruppen-Signatur (`groupSig`) weicht von `local` ab ODER `deletedAt` weicht ab. `needPhoto = !!merged._fotoRemote`. Eingaben unverändert.
- `meshReceipt(p, upTo)` → `p` (verändert): `clearPending(p.fts||{}, upTo)`; wenn `(p.updated||0) <= upTo`: `delete p._dirty; delete p._via; delete p._fuer`. Keine Herkunfts-Buchung (nur das Gateway protokolliert).
- `meshChunk(items, maxBytes)` → Array von Teilarrays, jedes mit `JSON.stringify(teil).length <= maxBytes` (gierig; ein einzelnes übergroßes Element bildet allein einen Teil); `[]` → `[]`.
- `meshEnvelope(t, from, ccp, seq, at, body)` → `Object.assign({v:1, id: from+'-'+seq, t, from, ccp, at}, body||{})`.
- `meshValidate(msg, ctx)` → `null` wenn gültig, sonst kurzer Grund-String (`'typ'`, `'ccp'`, `'from'`, `'id'`, `'zeit'`, `'unauth'`, `'groesse'`, `'inhalt'`). `ctx = {ccp, now, order, authed:{dev:true}, ccpIds:[…] (optional), bytes (optional)}`. Regeln: Objekt; `v===1`; `t` in `MESH_PROTO.types`; `from` Ganzzahl 1..99; `ccp===ctx.ccp`; `id` passt zu `/^\d{1,2}-\d{1,9}$/` und beginnt mit `from+'-'`; `at` Zahl ≤ `ctx.now + MESH_PROTO.futureMs`; `ctx.bytes > MESH_PROTO.maxMsg` → `'groesse'`; `t!=='hello'` und `!ctx.authed[from]` → `'unauth'`; typspezifisch (`'inhalt'`): `inv.pats` Objekt mit Arrays aus 9 Zahlen; `req.pats` Objekt mit Arrays aus Strings ∈ `ctx.order`; `delta.pats` Array, jedes Element `id` ~ `/^[A-Za-z0-9_-]{1,40}$/`, `ccpId` ∈ `ctx.ccpIds` (falls `ctx.ccpIds` gegeben), alle `fts.*.t` Zahlen ≤ `now+futureMs`; `rcpt.pats` Array aus `{id, upTo:Zahl}`; `foto-req`: `pid` ID-Muster, `to` Ganzzahl 1..99; `lock`: `pid`, `by` String ≤ 40 Zeichen, `lockedAt` Zahl, `release` boolean; `meta`: `hub` Ganzzahl|null, `devs` Array; `hb`: `op` String ≤ 40, `open` Ganzzahl ≥ 0, `online` boolean.
- `meshDedup(seen, id, max)` → `true` wenn neu (wird in `seen` eingetragen), `false` wenn schon gesehen. `seen = {ids:{}, order:[]}`; über `max` Einträge → ältester fliegt (LRU-Grenze).
- `meshHub(devNos)` → kleinste Gerätenummer ≥ 1 oder `null` (0/negativ/NaN ignoriert).
- `meshNext(st, ev)` → neuer Zustand (reine Reducer-Funktion, `st` unverändert). Zustand `{s, hub, since, retry, announce}` mit `s ∈ off|seeking|connecting|spoke|hub|full|denied`. Ereignisse: `start{ok,now}` → ok ? seeking(since=now, retry 0, hub null) : off · `stop`/`bg` → off(hub null) · `denied` → denied · `full{now}` → full(since now) · `peers{devs, me, now, settle}`: `h = meshHub(devs < me)`; in seeking/full: `h` → connecting(hub h, since now); sonst `now - since >= settle` → hub(hub me), sonst unverändert; in hub: `h` → connecting(hub h, since now, announce h) (Handshake); sonst unverändert · `connected{dev,now}`: connecting ∧ dev===hub → spoke(since now, retry 0, announce gelöscht) · `lost{dev,now}`: spoke ∧ dev===hub → seeking(hub null, since now) · `timeout{now}`: connecting → seeking(retry+1, since now) · `meta{hub,me,now}`: `hub` ∧ hub!==st.hub ∧ hub<me → connecting(hub); `hub===me` → hub(hub me) · `tick{now}`: full ∧ now-since ≥ `MESH_PROTO.fullRetryMs` → seeking; connecting ∧ now-since ≥ `MESH_PROTO.inviteTimeoutMs` → wie timeout · unbekannte Ereignisse → unverändert.
- `meshLockApply(p, msg, now, ttl)` → `true` wenn `p` verändert. `msg={by, lockedAt, release, mm}`. `release`: nur wenn `p.lockedBy===msg.by` → `lockedBy=null, lockedAt=null`. Sonst: bestehende fremde, frische Sperre (`p.lockedBy && p.lockedBy!==msg.by && now-p.lockedAt < ttl`) bleibt, außer `msg.mm===true` (MasterMedic-Override gewinnt, D6.7-07); andernfalls `lockedBy=msg.by, lockedAt=msg.lockedAt`.
- `meshPhotoAccept(name, p)` → `{ok, pid, stamp, mime}`; `name = 'foto:<pid>:<stamp>:<mime>'`; `ok` nur wenn `pid===p.id` und (`p.fts.foto` fehlt ODER `stamp >= p.fts.foto.t`). Verändert `p` nicht (das Setzen von `photo` macht der Aufrufer in Plan 04).
- `meshPillText(s, n, x)` → deutscher Pillentext: `x={hub, bg, training, akku}`. off ∧ training → `'Mesh: im Training aus'`; off ∧ bg → `'Mesh aus — App im Hintergrund'`; off → `'Mesh aus'`; seeking → `'Mesh: suche Geräte …'`; connecting → `'Mesh: verbinde mit Gerät <hub> …'`; spoke → `'Mesh: <n> Geräte · Nabe <hub>'` (n=1 → `'1 Gerät'`); hub → `'Mesh: <n> Geräte · Nabe: dieses Gerät'`; full → `'Stern voll — Gerät verbindet sich, sobald ein Platz frei ist'` (D6.7-09); denied → `'Mesh: Lokales Netzwerk in Einstellungen erlauben'`; Suffix bei `x.akku` → `' · Bildschirm bleibt an'` (D6.7-08).
- `meshDeviceRows(meshDevs, serverDevs, now)` → sortiertes Array (nach `device_no`) von Zeilenobjekten für `devStatus`/`devLabel`. `meshDevs={dev:{op, last, open, online}}`, `serverDevs` Array aus `fetchDevices()` oder `null`. Je Gerätenummer: Mesh-Eintrag mit `now-last < 30000` → `{device_no, operator:op, last_seen:last, open_n:open, via:'mesh', kennung, ccp_id}` (kennung/ccp_id aus dem Server-Eintrag, sonst `''`/`null`); sonst Server-Eintrag + `via:'server'`; nur veralteter Mesh-Eintrag → Mesh-Felder mit `via:'mesh'` (devStatus liefert dann „außer Reichweite“). Mesh frisch schlägt `left_at`/`lost_at` des Servers (Gerät lebt nachweislich).
- `devLabel(d, now, o)` (bestehend, erweitern): bei Status `verbunden` und `d.via==='mesh'` → head + `' (Mesh)'`, bei `d.via==='server'` → `' (Server)'`; ohne `d.via` unverändert (bestehende Tests bleiben grün).
- `meshNative()` → `null` außerhalb der Hülle (kein `window.Capacitor` / `isNativePlatform()` false / Plugin `MESH_PROTO.jsName` nicht verfügbar), sonst `{call:function(m,o){return C.nativePromise(MESH_PROTO.jsName, m, o||{});}, on:function(ev,cb){return C.addListener(MESH_PROTO.jsName, ev, cb);}}` — alles in `try`, wirft nie. Darf `window`/`MESH_PROTO` lesen (Test setzt `window` im Scope per `evalInScope`).
