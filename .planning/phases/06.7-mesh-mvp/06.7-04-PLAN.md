## Plugin-API (aus Plan 02 `<context>`, hier verbindlich)
`N = meshNative()` → `N.call('start',{ccpId, secret, deviceNo, hub})` → `{ccpHash}`; `N.call('stop')`; `N.call('setRole',{hub, full})`; `N.call('connect',{to})`; `N.call('send',{to:'all'|peerKey, json})`; `N.call('sendResource',{to, name, base64})`; `N.call('setKeepAwake',{on})`; `N.call('status')`. Events: `N.on('peers', fn({peers:[{key, dev, ccp, full, state}]}))`, `N.on('message', fn({from, json}))`, `N.on('resource', fn({from, name, base64}))`, `N.on('state', fn({s, detail}))`. `connected` bedeutet: Transport-Authentisierung bestanden. Alle `call` sind Promises — immer `.then(null, function(){})`, nie `await` im Aktionspfad.

## Controller-Zustand (eine globale Struktur, Kommentar je Feld)
`var _mesh = {native:null, st:{s:'off', hub:null, since:0, retry:0}, ccpHash:'', me:0, peers:{}, keys:{}, authed:{}, seen:{ids:{}, order:[]}, seq:0, devs:{}, full:false, bg:false, denied:false, lastError:'', lastInv:0, lastInvSig:'', lastHb:0, lastMeta:0, lastRcpt:0, lastConnect:0, deltaQ:{}, deltaTimer:null, gwTimer:null, fotoWait:{}, tick:null, awake:false, pillTxt:''}`.
- `peers[key] = {dev, ccp, full, state}`; `keys[dev] = key`; `authed[dev] = true` nur für `state==='connected'`; `devs[dev] = {op, last, open, online}` aus `hello`/`hb`/`meta.devs`.

## Rollen und Routing
- `meshActive()` = `st.s` ∈ `spoke|hub`. `meshTargets()` = Speiche → `keys[st.hub]`, Nabe → `'all'`.
- Nur Speichen rufen `connect`; die Nabe nie (RESEARCH Pattern 3). Reducer-Übergang nach `connecting` → `connect({to: keys[hub]})`, frühestens nach Backoff `5000 * 2^min(retry,2)` ms seit `lastConnect`.
- Reducer liefert `announce:h` (Nabe sieht kleinere Nummer) → ERST `meshSend('meta',{hub:h})` an alle Speichen, DANN `setRole({hub:false})`, dann `connect`. Reducer → `hub` → `setRole({hub:true, full:false})`. Nabe: `authed`-Speichen ≥ `MESH_PROTO.maxSpokes` → `setRole({hub:true, full:true})`, sonst `full:false`. Speiche: Nabe wirbt `full==='1'` → Reducer `full`.
- Relay (nur Nabe): `delta`, `rcpt`, `lock` → unverändertes `json` an alle `authed`-Speichen außer Absender; `foto-req` → nur an `keys[msg.to]`, falls die Nabe das Foto nicht selbst hat; `inv`/`req`/`hello`/`hb` werden NICHT weitergeleitet; `meta` sendet nur die Nabe.

## Nachrichtenfluss
- Verbindung hergestellt (`connected` neu) → `meshSend('hello',{op, mm:masterMedic||'', app:APP_VERSION, online:netLikelyUp(), re:false}, key)`; Empfänger antwortet mit `re:true` (keine Schleife) und sendet danach `inv`.
- `inv`: `meshSendInv(toKey)` = `meshInventory(patients.concat(_tombs), MESH_GROUPS_ORDER)`; übersteigt das JSON `MESH_PROTO.maxMsg`, Einträge als `[id, stempel]`-Paare mit `meshChunk` teilen und mehrere `inv` senden. Zeitplan: beim `hello`, danach alle `MESH_PROTO.invMs`, wenn sich das Inventar-JSON seit dem letzten Senden geändert hat (`lastInvSig`), sonst spätestens alle 120 s.
- `inv` empfangen → `need = meshDiff(mein Inventar, msg.pats, msg.order||MESH_GROUPS_ORDER)` → bei Einträgen `meshSend('req',{pats:need}, fromKey)`.
- `req` empfangen → je `pid`: `p = await sGet('ccp_pat_'+pid)`; `!p || p.demo || p.training` → überspringen; `meshDelta(p, gruppen, FGROUPS)`; Liste mit `meshChunk(…, MESH_PROTO.chunk)` → je Teil `meshSend('delta',{part:i+1, of:n, pats:teil}, fromKey)`.
- `delta` empfangen → je Eintrag `meshApplyIncoming(inc, msg.from)`; danach `meshAfterApply(...)`; Nabe: Relay.
- `meshApplyIncoming(inc, fromDev)`: `local = await sGet('ccp_pat_'+inc.id)`; `r = meshApply(local, inc, FGROUPS)`; `!r.changed && !r.isNew` → `false`. `m = normalize(r.merged)`; `m._dirty = true`; Provenienz: besitzt `m` eigene unbestätigte Stempel (`fts.*.p`) → `_via/_fuer` unverändert lassen, sonst `m._via='mesh'; m._fuer = meshOriginDev(inc) || fromDev` (`meshOriginDev` = `d` des jüngsten `fts`-Eintrags des Deltas); `m._sig = groupSigs(m, FGROUPS)`; `await sSet('ccp_pat_'+m.id, m)`; Speicher: Grabstein (`m.deletedAt || m.status==='verworfen'`) → aus `patients` entfernen, in `_tombs` ersetzen/einfügen; sonst in `patients` ersetzen/einfügen (per `id`) und aus `_tombs` entfernen. Rückgabe `r` (für `needPhoto`).
- `meshAfterApply(changed, needPhotoIds)`: `state.view` weder `patient` noch `checklist` → `render()` (wie der Realtime-Handler: im Patienten-View NIE neu rendern — Fokusverlust); ist der offene Patient betroffen → `state.edit` auf das aktualisierte Objekt aus `patients` zeigen lassen (Sperrfelder beibehalten) und bei `needPhoto` → `meshRequestPhoto(id)`. Gateway: `netLikelyUp() && sb()` → `gwTimer` (1,5 s) → `loadPatients().then(function(){ if(state.view==='home') render(); })` (flushPendingPatients lädt alle `_dirty` hoch, D6.7-04).
- `rcpt` empfangen → je `{id, upTo}`: `p = await sGet(...)` → `meshReceipt(p, upTo)` → `sSet`; `patients`-Objekt ebenso; `state.view==='home'` → `render()` (Zähler „nicht synchronisiert“). Nabe: Relay.
- `rcpt` senden: `meshTick` → `_meshRcptQ.length && now - lastRcpt >= MESH_PROTO.rcptBundleMs` → `meshSend('rcpt',{pats:_meshRcptQ.splice(0)}, meshTargets())` (bei > 24 KB mit `meshChunk` teilen).
- `lock` empfangen → `p = patients.find(id===pid)`; `meshLockApply(p, msg, nowMs(), LOCK_TTL)` → `sSet`; ist es der offene Patient → dieselbe Logik wie im Realtime-Handler (`subscribeRealtime`: Wartender übernimmt bei frei/abgelaufen, Bearbeiter erkennt fremde Übernahme → `state.readonly`, `render()`, `toast`). Nabe: Relay.
- `lock` senden: `acquirePatientLock`/`releasePatientLock` nach `pushLock(p)` → `meshSend('lock',{pid:p.id, by:operator, lockedAt:p.lockedAt||0, release:!p.lockedBy, mm:isMasterMedic()}, meshTargets())` (nur wenn `meshActive()`). Sperr-Heartbeat (5-s-Intervall `:5308`): vor `var client=sb(); if(!(client && _ccpId)) return;` ein Mesh-Zweig: `!netLikelyUp() && meshActive() && state.edit.lockedBy===operator && nowMs()-_lockBeat>15000` → `_lockBeat`/`lockedAt` setzen, `meshSend('lock', …)`, `return`.
- `hb` senden: alle `MESH_PROTO.hbMs` wenn `meshActive()`: `{op:operator||'', open:patients.filter(_dirty).length, online:netLikelyUp(), offQ: Alter der letzten Uhrprobe (ms) oder -1}`. `hb` empfangen → `devs[from] = {op, last:nowMs(), open, online}`; kein Relay.
- `meta` senden (nur Nabe): alle 30 s und bei Rollenwechsel: `{hub:me, mm:masterMedic||'', full, devs:[{dev, op, last, open, online} für devs ∪ ich]}`. `meta` empfangen → Reducer `meta{hub, me}`; `msg.mm` ist String und `!netLikelyUp()` → `masterMedic = msg.mm` (D6.7-02: offline verteilt das Mesh die Rolle; online bleibt der Server Autorität über `loadMeta`); `devs` in `_mesh.devs` einmischen (nur frischere `last`).
- `foto-req` senden: im `openpat`-Handler nach `state.view="patient"`: `state.edit._fotoRemote && !state.edit.photo` → `meshRequestPhoto(id)` = `meshSend('foto-req',{pid, to:(p._fuer|0)}, meshTargets())`.
- `foto-req` empfangen: `p = await sGet(...)`; `p && p.photo` → Data-URI zerlegen (`data:<mime>;base64,<b64>`) → `N.call('sendResource',{to:fromKey, name:'foto:'+pid+':'+((p.fts&&p.fts.foto&&p.fts.foto.t)||0)+':'+mime, base64:b64})`; sonst Nabe mit `keys[msg.to]` → Relay dorthin und `fotoWait[pid] = (fotoWait[pid]||[]).concat(fromKey)`; sonst ignorieren.
- `resource` empfangen: `name` parsen, `p = await sGet(pid)`, `acc = meshPhotoAccept(name, p)`; `acc.ok` → `uri = 'data:'+acc.mime+';base64,'+base64`; `safePhoto(uri)` leer → verwerfen; sonst `p.photo = uri; delete p._fotoRemote; p._dirty = true; p._via = p._via||'mesh'; p._fuer = p._fuer||(dev des Absenders)`; `sSet`; `patients`-Objekt aktualisieren; offener Patient → `render()` nur, wenn `state.edit.id===pid` und kein Eingabefeld fokussiert ist (`document.activeElement.tagName` nicht INPUT/TEXTAREA), sonst beim nächsten Render. Nabe: an `fotoWait[pid]` per `sendResource` weiterreichen, dann löschen.
