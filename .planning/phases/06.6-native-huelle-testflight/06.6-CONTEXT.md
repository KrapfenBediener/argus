# Phase 6.6: Native Hülle & TestFlight (Owner-Label „9a“) — Context

**Erstellt:** 2026-10-17 (Orchestrator aus Owner-Entscheiden; kein Discuss-Phase-Dialog, Owner schläft — Entscheide unten sind vom Owner im Chat getroffen, Rest ist dokumentiertes Ermessen)

<domain>
## Phase Boundary
Die unveränderte Single-File-Web-App (`index.html` + `config.js` + `vendor/` + `fonts/` + Icons) wird in eine Capacitor-iOS-Hülle gepackt, läuft im Simulator, auf eigenen iPhones (freie Apple-ID) und später über TestFlight (Developer-Account, Freigabe steht aus). Gleiche Bedienung, gleiches Backend, Local-first. Kein Mesh, kein MDM, kein Android.

**Umgebung auf dem Entwickler-Mac (Stand 2026-10-17):** macOS 15.7, Node 22.22, npm 10.9, **kein Xcode** (nur Command Line Tools, `xcodebuild`/`simctl` fehlen), kein CocoaPods, kein Homebrew, kein `gh`; ~34 GB frei. Owner installiert Xcode nach dem Mittagsschlaf; Developer-Account wird parallel beantragt (Freigabe 24–48 h). → Alles, was ohne Xcode geht (Projekt, Skripte, App-Anpassungen, Doku, Tests), wird JETZT gebaut; Build/Simulator/TestFlight sind Owner-Checkpoints.
</domain>

<decisions>
## Implementation Decisions (Owner, 2026-10-17)
- **D6.6-01 Eigentumslinie:** Apple-Developer-Account als **Einzelperson** mit eigener Apple-ID (nicht dienstlich). Bundle-ID im Namensraum des Eigentümers (z. B. `de.gaborszeman.argus` — Planner wählt, muss zur Eigentumslinie passen; keine Polizei-Domain).
- **D6.6-02 Reihenfolge:** 6.6 VOR Phase 7; Mesh (6.7) baut auf der Hülle auf. Übergabe (Phase 8) folgt nach Phase 9.
- **D6.6-03 Web-App bleibt unverändert ausgeliefert:** Die PWA auf GitHub Pages bleibt der Hauptweg für heute; die Hülle lädt dieselben Dateien lokal gebündelt (Local-first — **kein** `server.url` auf die Pages-Domain, sonst keine Offline-Fähigkeit beim ersten Start).
- **D6.6-04 Deep-Link `#code=XXXX-XXXX`:** Freischalt-Link/QR öffnet die App und löst den Code automatisch ein (das war die ursprüngliche Owner-Motivation für nativ). Minimum: Custom-URL-Scheme; Universal Link nur, wenn `apple-app-site-association` auf der Pages-Domain nachweislich funktioniert (Research prüft Content-Type/.well-known auf GitHub Pages).
- **D6.6-05 Keychain für JWTs/Codes:** Zugangs-JWTs (`argus_jwt`, `argus_jwt_by_pid`, `argus_code`, Master-Flag) wandern in die Keychain (Capacitor-Plugin); Fallback `localStorage`, wenn das Plugin fehlt (gleicher Code läuft weiterhin als PWA!). Patientendaten bleiben in der bestehenden Speicherschicht (`sGet/sSet`-Naht laut CLAUDE.md), nicht in der Keychain.
- **D6.6-06 Keine nativen Dialoge** (CLAUDE.md) — auch in der Hülle `confirmModal/promptModal`. Keine neuen UI-Komponenten; ARGUS-Design unverändert.
- **D6.6-07 Versionskopplung:** native `CFBundleShortVersionString` = `APP_VERSION`; Build-Nummer monoton. Konsistenztest in `tests/` (reine Dateiprüfung, kein Xcode nötig).
- **D6.6-08 Owner-Checkpoints statt Automatik:** Xcode-Build, Simulator-Smoke-Test, Signing, TestFlight-Upload sind `checkpoint:human-action`; die Doku (`docs/NATIVE-HUELLE.md`) muss so geschrieben sein, dass der Owner sie ohne Rückfrage abarbeiten kann (Schritte, Screenshots nicht nötig, exakte Menüpfade).

### Claude's Discretion (Researcher/Planner)
- Capacitor-Version (npm zeigt 8.5.3 für core/cli/ios) und Paketmanager (SPM bevorzugt, kein CocoaPods installiert). Mindest-iOS passend zu Dienst-iPhones (konservativ iOS 16+, prüfen).
- Ordnerstruktur `native/` (eigenes `package.json`, `capacitor.config.ts/json`, `www/` als Build-Ausgabe, gitignored); Kopierskript `native/scripts/sync-web.mjs` (idempotent; kopiert nur die gelisteten Dateien; schreibt `native-version.json`).
- Umgang mit PWA-Mechaniken in der Hülle: `isStandalone()` → true bei `window.Capacitor?.isNativePlatform()`; Service-Worker-Registrierung überspringen (WKWebView: kein SW im `capacitor://`-Schema); `checkForUpdate()` → in der Hülle Hinweis „Update über TestFlight/App“ statt `location.reload()` (version.json liegt gebündelt → nie neuer); `navigator.share` (Export) prüfen, ggf. `@capacitor/share`; Datei-Input mit `capture="environment"` (Kamera) in WKWebView prüfen; Geolocation-Berechtigungstext.
- WKWebView-Datenpersistenz: `localStorage`/IndexedDB in Capacitor sind persistent, aber Research soll bestätigen, ob iOS „Website-Daten“-Bereinigung die App treffen kann; ggf. `@capacitor/preferences` als Spiegel für die kritischen Schlüssel.
- Splash/Icon: aus `ARGUS_Icon.png`/`icon-192.png` generieren (Skript, keine Fremd-Assets).
- Statusleiste/Safe-Area: `viewport-fit=cover` ist in index.html vermutlich vorhanden — prüfen, Safe-Area-Insets in der Hülle testen (Checkpoint).
</decisions>

<specifics>
## Specific Ideas
- `native/scripts/sync-web.mjs` liest `sw.js` → PRECACHE_URLS als Quelle der Wahrheit für die zu bündelnden Dateien (plus Icons), damit PWA und Hülle nicht auseinanderlaufen.
- In `index.html` eine kleine Brücke `function isNativeShell(){ try{ return !!(window.Capacitor && window.Capacitor.isNativePlatform && window.Capacitor.isNativePlatform()); }catch(e){ return false; } }` — reine Funktion, testbar via `_extract.cjs`.
- Keychain-Zugriff hinter einer winzigen Fassade `secureGet/secureSet/secureDel` (async), die in der PWA auf `localStorage` fällt; nur die Zugangsschlüssel wandern, Migration beim ersten nativen Start (localStorage → Keychain, dann löschen).
- `docs/NATIVE-HUELLE.md` enthält drei Pfade: (A) Simulator ohne Account, (B) eigenes iPhone mit freier Apple-ID (7-Tage-Signatur), (C) TestFlight mit Developer-Account (App Store Connect, interne Tester ≤ 100, Export-Compliance „nur HTTPS“).
</specifics>
