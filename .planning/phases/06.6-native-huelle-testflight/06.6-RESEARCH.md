## Summary

Die Hülle ist mit Capacitor 8.5.3 (core/cli/ios) und Swift Package Manager machbar und — das ist der wichtigste Befund für „jetzt bauen, später Xcode" — **`npx cap add ios --packagemanager SPM` und `npx cap sync ios` laufen ohne Xcode**: `add` entpackt nur das mitgelieferte Template-Tarball und prüft, ob `@capacitor/ios` installiert ist; `sync` kopiert `webDir` nach `ios/App/App/public` (löscht den Zielordner vorher komplett), schreibt `CapApp-SPM/Package.swift` und überspringt den `xcodebuild clean`-Schritt mit einer Warnung, wenn `xcodebuild` fehlt (aus `@capacitor/cli@8.5.3` `dist/ios/add.js`, `dist/ios/update.js:290-297`, `dist/tasks/copy.js:144-147` gelesen). Xcode 26.0+ (macOS ≥ 15.6 — der Mac hat 15.7) wird erst für Paketauflösung, Build, Simulator, Signing, Archive und `agvtool` gebraucht. Deployment-Target des Templates ist iOS 15.0 — das deckt „konservativ iOS 16+" ab, ohne etwas zu ändern.

Für die Single-File-App ohne Bundler entscheidend: Die iOS-Seite injiziert per `WKUserScript` zum Dokumentstart sowohl `native-bridge.js` (liefert `window.Capacitor.isNativePlatform()`, `getPlatform()`, `isPluginAvailable()`) als auch für jedes registrierte native Plugin ein fertiges Objekt `window.Capacitor.Plugins.<jsName>` mit allen Methoden und `addListener` (`JSExport.swift:73-110`). Die `@capacitor/core`-JS-Runtime muss also **nicht** in `index.html` eingebunden werden; `window.Capacitor.Plugins.App.getLaunchUrl()` und ein eigenes `window.Capacitor.Plugins.SecureStore` sind direkt aufrufbar. `appUrlOpen` wird vom App-Plugin mit `retainUntilConsumed: true` gefeuert, d. h. auch ein Kaltstart per Link geht nicht verloren.

Supabase akzeptiert den Origin `capacitor://localhost` (Preflight `access-control-allow-origin: *`, GET echo des Origins, Realtime-WebSocket-Handshake `101`, live am 2026-10-17 gegen die Projektinstanz geprüft). Universal Links sind auf GitHub Pages technisch nicht ausgeschlossen (eine echte `*.github.io`-AASA wird mit `200 application/octet-stream` ausgeliefert; Apples aktuelle Doku und TN3155 nennen **keinen** Content-Type, nur HTTPS/kein Redirect/öffentlich erreichbar), scheitern aber an zwei harten Punkten: Associated Domains gibt es nicht mit einem Personal Team (nur mit bezahltem Developer Program), und die AASA muss am **Host-Root** (`https://<user>.github.io/.well-known/…`) liegen — bei einer Projekt-Seite ist das ein anderes Repository. Daher: Custom-Scheme `argus://` als Pflicht, Universal Link als optionale Stufe 2 nach Account-Freigabe. Für die Keychain wird ein eigenes ~60-Zeilen-Swift-Plugin empfohlen (Security.framework, `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`), statt eines der beiden Ein-Personen-Community-Plugins; `@capacitor/preferences` scheidet aus (UserDefaults, nicht Keychain).

**Primäre Empfehlung:** Jetzt `native/` mit Capacitor 8.5.3 + SPM scaffolden (4 npm-Pakete: core, cli, ios, app), Kopierskript aus `PRECACHE_URLS` + Icons + `UPDATE_SHEETS`, `isNativeShell()`-Brücke + Zugangs-Fassade in `index.html`, Info.plist (DE-Texte, `argus`-Scheme, Portrait, `ITSAppUsesNonExemptEncryption=false`), pbxproj-Versionsskript, Tests — und drei Owner-Checkpoints (Xcode-Build/Simulator, eigenes iPhone, TestFlight) in `docs/NATIVE-HUELLE.md`.
</research_summary>

### Pattern 1: Kopierskript aus der Quelle der Wahrheit (`sync-web.mjs`)
**Was:** Liest `sw.js` → `PRECACHE_URLS` (regex wie in `tests/consistency.test.cjs`) und `index.html` → `UPDATE_SHEETS` (via `tests/_extract.cjs`-Logik, `extractVarLiteral`), ergänzt feste Extras (`icon-180.png`, `icon-192.png`, `manifest.json`, `version.json`, `docs/fonts/*` falls von Update-Sheets genutzt), kopiert **nur** diese Dateien nach `native/www/` (vorher leeren), schreibt `www/native-version.json` `{version: APP_VERSION, build, syncedAt}`. Bündelt **nicht**: `sw.js`, `docs/leitung-*`, `docs/lage-*`, `legacy/`, `.planning/`.
**Warum:** PWA und Hülle laufen nicht auseinander; der bestehende Test „alle PRECACHE_URLS existieren" schützt beide. Die Update-Sheets sind relativ verlinkt (`docs/UPDATE_v0.32.html`) und würden in der Hülle sonst 404 liefern.
**Idempotenz:** zweimal laufen → identischer Baum (Test: Hash-Vergleich).

### Pattern 2: Native-Brücke als reine Funktionen in `index.html`

/* Native Hülle (Capacitor) erkennen — pure Funktion, testbar via _extract.cjs */
function isNativeShell(){
  try{ return !!(window.Capacitor && window.Capacitor.isNativePlatform && window.Capacitor.isNativePlatform()); }
  catch(e){ return false; }

### Pattern 3: Deep-Link — Kaltstart und Warmstart
```javascript
/* vor der bestehenden Start-IIFE-Logik (vor extractInviteCode()) */
async function adoptNativeLaunchUrl(){
  if(!isNativeShell()) return;
  var App=capPlugin('App'); if(!App) return;
  try{
    var r=await Promise.race([App.getLaunchUrl(), new Promise(function(res){ setTimeout(function(){res(null);},800); })]);
    var h=r&&r.url&&r.url.indexOf('#')>=0 ? r.url.slice(r.url.indexOf('#')) : '';
    if(h) history.replaceState(null,'',window.location.pathname+h);   /* → extractInviteCode() liest es wie gewohnt */
  }catch(e){}
  try{ App.addListener('appUrlOpen', function(ev){ handleIncomingUrl(ev&&ev.url); }); }catch(e){}
}
/* Warmstart: App läuft bereits */
async function handleIncomingUrl(url){
  var code=extractInviteCode(url||'');   /* extractInviteCode um optionalen Parameter erweitern (Default: location.hash) */
  if(!code) return;
  await redeemUrlCode(code);             /* = heutiger urlCode-Zweig der Start-IIFE, in Funktion gezogen; nutzt exchangeCode() */
  render();
}
```
`getLaunchUrl` ist Methode des App-Plugins; `appUrlOpen` wird mit `retainUntilConsumed: true` gesendet, d. h. wird vor Listener-Registrierung gepuffert `[VERIFIED: AppPlugin.swift:12,55,63,97]`. Das Timeout-Race hält Local-first (CLAUDE.md): Der Start blockiert nie auf die Bridge.

### Pattern 4: Zugangs-Fassade mit synchronem Lesen (für die ~30 bestehenden Aufrufstellen)
**Problem:** `sb()` (Z. 468), `jwtClaims`, `ensureJwtFor` u. a. lesen `localStorage.getItem('argus_jwt')` **synchron** bei jedem Aufruf; Keychain ist asynchron.
**Lösung:** Keychain = persistente Quelle, `sessionStorage` = synchroner Laufzeit-Cache (nativ), `localStorage` = PWA-Pfad (unverändert).
```javascript
var ACCESS_KEYS=['argus_jwt','argus_jwt_exp','argus_jwt_by_pid','argus_code','argus_is_master'];
function accessStore(){ return isNativeShell()? window.sessionStorage : window.localStorage; }
function accessGet(k){ try{ return accessStore().getItem(k); }catch(e){ return null; } }
function accessSet(k,v){ try{ accessStore().setItem(k,v); }catch(e){} secureWrite(k,v); }
function accessDel(k){ try{ accessStore().removeItem(k); }catch(e){} secureWrite(k,null); }
function secureWrite(k,v){ var S=isNativeShell()&&capPlugin('SecureStore'); if(!S) return;   /* PWA: nichts zu tun */
  (v===null? S.remove({key:k}) : S.set({key:k,value:String(v)})).catch(function(){}); }
async function hydrateAccessFromKeychain(){   /* einmal beim nativen Start, mit Timeout; danach Migration localStorage→Keychain */
  var S=isNativeShell()&&capPlugin('SecureStore'); if(!S) return;
  for(var i=0;i<ACCESS_KEYS.length;i++){ var k=ACCESS_KEYS[i];
    try{ var r=await S.get({key:k}); if(r&&r.value!=null){ sessionStorage.setItem(k,r.value); continue; } }catch(e){}
    try{ var legacy=localStorage.getItem(k); if(legacy!=null){ sessionStorage.setItem(k,legacy); await S.set({key:k,value:legacy}); localStorage.removeItem(k); } }catch(e){}
  }
}
```
Dann alle `localStorage.(get|set|remove)Item('argus_jwt…'|'argus_code'|'argus_is_master')` auf `accessGet/accessSet/accessDel` umstellen (reines Suchen/Ersetzen; Test-Gate verhindert Rückfall). Ergebnis: Secrets liegen nativ **nur** in der Keychain, nicht in der WebKit-LocalStorage-Datei; die PWA verhält sich exakt wie heute.

### Pattern 5: Eigenes Keychain-Plugin (Swift, ~60 Zeilen)
Registrierung laut offizieller Doku: Plugin-Klasse `CAPPlugin, CAPBridgedPlugin` mit `identifier`, `jsName`, `pluginMethods`; Registrierung in einer `CAPBridgeViewController`-Subklasse via `bridge?.registerPluginInstance(...)` in `capacitorDidLoad()`; die Subklasse wird in `Main.storyboard` als Klasse des View Controllers eingetragen `[CITED: capacitorjs.com/docs/ios/custom-code]`. Code in §Code Examples.

### Anti-Patterns to Avoid
- **`server.url` auf die Pages-Domain:** verletzt D6.6-03 und Local-first; Capacitor-Doku: „intended for live reload, not production" `[CITED: docs/config]`.
- **`ios/App/App/public` oder `capacitor.config.json` im iOS-Ordner von Hand editieren:** werden bei jedem `cap sync` gelöscht/überschrieben `[VERIFIED: copy.js:144-147, Template-.gitignore]`.
- **`CapApp-SPM/Package.swift` editieren:** „DO NOT MODIFY — managed by Capacitor CLI" `[VERIFIED: Template]`.
- **`@capacitor/core` als `<script>` in index.html einbinden:** unnötig (native Bridge liefert alles) und würde in der PWA Web-Fallbacks laden.
- **Zugangs-Secrets weiter in `localStorage` spiegeln „zur Sicherheit":** macht die Keychain-Härtung wirkungslos.
- **Capacitor-Patch-Version floaten (`^8.5.3`):** `cap sync` schreibt `Package.swift` mit `from: "8.0.0"` — Xcode löst dann selbständig; npm- und SPM-Stand sollen deterministisch bleiben → `--save-exact` und `Package.resolved` committen.

| Problem | Nicht selbst bauen | Stattdessen | Warum |

| iOS-Projekt-Skelett (WKWebView, Scheme-Handler, Bridge) | eigenes Xcode-Projekt mit WKWebView | `npx cap add ios --packagemanager SPM` | Template enthält Scheme-Handler für `capacitor://`, Cookie/Logging-Bridge, SceneDelegate-Proxy, Debug-xcconfig `[VERIFIED]` |

<common_pitfalls>
## Common Pitfalls

### Pitfall 1: Xcode-Installation scheitert am Plattenplatz
**Was:** 34 GB frei; Xcode 26 plus iOS-26-Simulator-Runtime brauchen nach Community-Schätzungen 20–30 GB, der App-Store-Download temporär mehr. **Warum:** Runtimes werden separat heruntergeladen. **Vermeiden:** vor dem Download ≥ 40 GB freimachen (`df -h /`), nur die iOS-Runtime laden (`xcodebuild -downloadPlatform iOS`), Xcode-Download-Cache danach löschen. **Warnsignal:** Runtime-Download hängt bei „Preparing…". `[ASSUMED]`

### Pitfall 2: `cap sync` ohne Xcode meldet Warnungen — das ist korrekt
**Was:** „Unable to find xcodebuild. Skipping xcodebuild clean step…" und ggf. „Skipping pod install" sind erwartet `[VERIFIED: update.js:288,297]`. **Vermeiden:** in `docs/NATIVE-HUELLE.md` als „normal" dokumentieren; `npx cap doctor ios` erst nach Xcode-Installation als Gate verwenden.

### Pitfall 3: Hand-Edits in `ios/App/App/public` oder `ios/App/App/capacitor.config.json`
**Was:** beide werden bei jedem `cap sync`/`copy` gelöscht bzw. überschrieben `[VERIFIED: copy.js:144-147, Template-.gitignore]`. **Vermeiden:** nur `native/capacitor.config.json` und den Repo-Stamm ändern; Test prüft, dass `public/` gitignored ist.

### Pitfall 4: Install-Screen statt Code-Einlösung in der Hülle
**Was:** `isStandalone()` liefert im WKWebView `false` → `#code=` zeigt den Install-Screen (Z. 5382/5415) und der Einmal-Code wird nie eingelöst. **Vermeiden:** Pattern 2 (`isNativeShell()` zuerst). **Warnsignal:** Simulator zeigt „Zum Home-Bildschirm hinzufügen"-Anleitung.

### Pitfall 5: Update-Banner/Reload in der Hülle
**Was:** `version.json` liegt gebündelt → Banner nie; `updateNow()` würde `location.reload()` ausführen — sinnlos. **Vermeiden:** `checkForUpdate()` nativ sofort zurückkehren; in der Info-/Intro-Ansicht Text „Updates kommen über TestFlight" mit `App.getInfo().build` anzeigen (bestehende Textkomponenten).

### Pitfall 6: Relative Update-Sheets und Fonts fehlen im Bundle
**Was:** `UPDATE_SHEETS` verweisen auf `docs/UPDATE_v0.xx.html` (nicht in `PRECACHE_URLS`) → im Bundle 404. **Vermeiden:** `sync-web.mjs` kopiert `UPDATE_SHEETS`-Ziele (und `docs/fonts/`, falls referenziert); Test „jede referenzierte Datei existiert im `www`-Baum".

### Pitfall 7: Kamera-Absturz ohne Usage-Description
**Was:** Wahl „Foto aufnehmen" im Datei-Picker beendet die App ohne `NSCameraUsageDescription` `[CITED: Apple-Doku + Foren]`. **Vermeiden:** drei deutsche Texte in Info.plist (Kamera, Fotomediathek, Standort) — Test prüft Vorhandensein und Nicht-Leerheit. **Warnsignal:** Crash-Log „attempted to access privacy-sensitive data without a usage description".

### Pitfall 8: Kopfzeile unter der Statusleiste / Banner unter dem Home-Indikator
**Was:** keine `safe-area-inset`-Nutzung im CSS; WebView ist Vollbild. **Vermeiden:** CSS-Padding mit `env()` (Frage 6); Checkpoint auf iPhone-Simulator mit Dynamic Island.

### Pitfall 9: Keychain überlebt die Deinstallation
**Was:** Nach Löschen + Neuinstallation ist `localStorage` leer (kein `argus_verified`, keine Präsidien), aber die Keychain liefert noch `argus_jwt`/`argus_code` → inkonsistenter Zustand (Zugang ohne Freischaltungen, ggf. „gesperrt" trotz JWT). **Vermeiden:** `hydrateAccessFromKeychain()` erkennt „Keychain hat JWT, aber `localStorage` hat weder `argus_verified` noch `argus_unlocked`" und **verwirft** die Keychain-Einträge (frische Installation gewinnt) — oder spiegelt zusätzlich `argus_verified` in die Keychain; Planner entscheidet, Test deckt den Zweig ab. `[ASSUMED: Persistenzverhalten]`

### Pitfall 10: Sync-Lücke der Fassade
**Was:** Wird eine `localStorage.setItem('argus_jwt', …)`-Stelle übersehen (z. B. Z. 751/833/877/4659), schreibt sie nativ in den falschen Store → nach App-Neustart ist das JWT weg. **Vermeiden:** Test-Gate „kein direkter `localStorage`-Zugriff auf ACCESS_KEYS außerhalb der Fassade" (Regex auf dem Inline-Script).

### Pitfall 11: Bundle-ID/Team zu spät festgelegt
**Was:** `appId` wird bei `cap add` in die pbxproj geschrieben; späterer Wechsel = Hand-Edit an mehreren Stellen und neue App-ID im Portal. **Vermeiden:** `appId` vor `cap add` final (D6.6-01). Template-Default `com.getcapacitor.App` darf nie signiert werden.

### Pitfall 12: Universal Link als Pflicht eingeplant
**Was:** Personal Team kann kein Associated-Domains-Entitlement; AASA muss am Host-Root des Pages-Hosts liegen; CDN-Cache 24 h/1 Woche. **Vermeiden:** nur `argus://` als Pflicht; Universal Link separater Plan mit eigenem Checkpoint `swcutil dl`.

### Pitfall 13: Simulator hat keine Kamera, kein echtes Keychain-Verhalten bei Sperre, keinen TestFlight
**Vermeiden:** Checkliste trennt Simulator-Tests (Code einlösen, CCP eröffnen, Offline/Online, Safe Area, Deep Link per `xcrun simctl openurl booted "argus://unlock#code=…"`) von Geräte-Tests (Foto, Teilen, Standort, 7-Tage-Signatur).

### Pitfall 14: `.planning/` und `docs/NATIVE-HUELLE.md` sind öffentlich
**Vermeiden:** keine Team-ID, keine App-Store-Connect-Interna, keine D-06-Dateinamen in diese Dokumente.
</common_pitfalls>

### `ArgusSecureStorePlugin.swift` (eigenes Plugin, Security.framework)
```swift
// Quelle des Registrierungsmusters: capacitorjs.com/docs/ios/custom-code
import Capacitor
import Security

@objc(ArgusSecureStorePlugin)
public class ArgusSecureStorePlugin: CAPPlugin, CAPBridgedPlugin {
    public let identifier = "ArgusSecureStorePlugin"
    public let jsName = "SecureStore"
    public let pluginMethods: [CAPPluginMethod] = [
        CAPPluginMethod(name: "get",    returnType: CAPPluginReturnPromise),
        CAPPluginMethod(name: "set",    returnType: CAPPluginReturnPromise),
        CAPPluginMethod(name: "remove", returnType: CAPPluginReturnPromise)
    ]
    private var service: String { Bundle.main.bundleIdentifier ?? "argus" }
    private func query(_ key: String) -> [String: Any] {
        [kSecClass as String: kSecClassGenericPassword,
         kSecAttrService as String: service,
         kSecAttrAccount as String: key]
    }
    @objc func get(_ call: CAPPluginCall) {
        guard let key = call.getString("key") else { return call.reject("key fehlt") }
        var q = query(key); q[kSecReturnData as String] = true; q[kSecMatchLimit as String] = kSecMatchLimitOne
        var item: CFTypeRef?
        let status = SecItemCopyMatching(q as CFDictionary, &item)
        if status == errSecSuccess, let data = item as? Data, let s = String(data: data, encoding: .utf8) {
            call.resolve(["value": s])
        } else { call.resolve(["value": NSNull()]) }
    }
    @objc func set(_ call: CAPPluginCall) {
        guard let key = call.getString("key"), let value = call.getString("value"),
              let data = value.data(using: .utf8) else { return call.reject("key/value fehlt") }
        SecItemDelete(query(key) as CFDictionary)
        var q = query(key)
        q[kSecValueData as String] = data
        q[kSecAttrAccessible as String] = kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly
        let status = SecItemAdd(q as CFDictionary, nil)
        status == errSecSuccess ? call.resolve() : call.reject("Keychain-Fehler \(status)")
    }
    @objc func remove(_ call: CAPPluginCall) {
        guard let key = call.getString("key") else { return call.reject("key fehlt") }
        let status = SecItemDelete(query(key) as CFDictionary)
        (status == errSecSuccess || status == errSecItemNotFound) ? call.resolve() : call.reject("Keychain-Fehler \(status)")
    }
}
```

## Security Domain

`security_enforcement` ist in `.planning/config.json` nicht gesetzt → aktiviert.

### Anwendbare ASVS-Kategorien
| ASVS | Zutreffend | Standard-Kontrolle |
|---|---|---|
| V2 Authentication | ja (Einmal-Code → JWT, bestehend) | unverändert: `argus_exchange_code`-RPC verbraucht den Code serverseitig; Deep-Link ändert nur den Transportweg des Codes |
| V3 Session Management | ja | JWT in **Keychain** (`AfterFirstUnlockThisDeviceOnly`), Laufzeit in `sessionStorage`; Ablauf `argus_jwt_exp` bleibt |
| V4 Access Control | ja (RLS serverseitig) | unverändert; Origin `capacitor://localhost` ändert RLS nicht |
| V5 Input Validation | ja | `extractInviteCode` validiert per Regex `[A-Za-z0-9]{4}-?[A-Za-z0-9]{4}`; eingehende `appUrlOpen`-URLs nur durch diese Funktion, nie in DOM/`innerHTML` |
| V6 Cryptography | ja | **nicht selbst bauen** — Security.framework-Keychain; keine WebCrypto-Eigenverschlüsselung |
| V8 Data Protection | ja | Secrets nicht in WebKit-LocalStorage (nativ); Patientenfotos wie bisher lokal (Datenschutz-SPEC gilt weiter); `ITSAppUsesNonExemptEncryption=false` korrekt, da nur TLS |
| V12 Files/Resources | ja | Bundle enthält nur gelistete Dateien; keine `docs/leitung-*`/`lage-*`; kein `server.url` |
| V14 Configuration | ja | `loggingBehavior: production` (keine Bridge-Logs mit JWTs), `webContentsDebuggingEnabled` default false im Release |

### Bekannte Bedrohungsmuster für diesen Stack
| Muster | STRIDE | Standard-Mitigation |
|---|---|---|
| Fremd-App ruft `argus://unlock#code=…` mit geratenen Codes auf (Scheme ist nicht exklusiv) | Spoofing/Elevation | Codes sind Einmal-Codes, serverseitig verbraucht und ratenbegrenzt (bestehend); kein lokaler Vertrauensgewinn allein durch den Link; Universal Links (Stufe 2) wären exklusiv |
| Deep-Link-URL in UI reflektiert (XSS) | Tampering | nur Regex-Extraktion, `esc()` bei Anzeige (bestehendes Muster, `logic.test.cjs`) |
| JWT in WebKit-Datenbank (Backup, Forensik) | Information Disclosure | Keychain `ThisDeviceOnly` (nicht in iCloud-Backup migrierbar), `sessionStorage` statt `localStorage` nativ |
| Keychain-Reste nach Deinstallation → Geisterzugang | Elevation | Reinstall-Erkennung in `hydrateAccessFromKeychain` (Pitfall 9) |
| Bridge-Logging von Plugin-Argumenten (JWT) in Xcode-Konsole | Information Disclosure | `loggingBehavior: production`; `set()`-Aufrufe nie mit `console.log` |
| Supply Chain (npm) | Tampering | nur 4 Pakete, exakt gepinnt, `package-lock.json` committed, keine `postinstall` `[VERIFIED]`; Owner-Checkpoint vor `npm install` |
| Debug-Build an Tester | Information Disclosure | TestFlight nutzt Release-Konfiguration; `CAPACITOR_DEBUG` nur in `debug.xcconfig` |
| Veröffentlichung interner Angaben | Information Disclosure | `.planning/` und `docs/NATIVE-HUELLE.md` sind öffentlich: keine Team-ID, keine App-Store-Connect-IDs, keine D-06-Namen |
