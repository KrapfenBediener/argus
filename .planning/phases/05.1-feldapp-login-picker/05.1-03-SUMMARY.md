- **Pro-Person-Login im Feld** — ein Freischalt-Feld, Auto-Erkennung: erst `argus_exchange_code` (CR-02 weist Person-Codes sauber ab), dann `exchangePersonCode()`-Fallback (NUR wenn der erste Fehler kein „gesperrt" war). - **Verstärkter SCHULUNG-Banner** — permanent, vollbreit, `#F2B600`, fetter Text „🎓 SCHULUNGSUMGEBUNG — keine echten Patientendaten"; ersetzt den alten kleinen Inline-Hinweis.
- **Bewusste Moduswechsel-Bestätigung** — `confirmModal` sowohl beim Tab-Wechsel als auch bei Auswahl eines Präsidiums, das den Modus ändert (T-053-02, „Du wechselst von ECHTBETRIEB zu SCHULUNG … niemals echte Patientendaten").
- **Twin-Scope-Gap-Closure (Migration 0019, LIVE)** — siehe Deviations.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 — Missing Critical] Twin-Scope-Schreib-/Lesezugriff fehlte (RLS-Denied)**
- **Found during:** Task 3 (Browser-Checkpoint, live backend)
- **Issue:** `argus_exchange_person_code` (aus 0015) gibt für eine Person-Sitzung ein JWT mit nur EINER `praesidium_id` (Echt-Präsidium) aus. Der Schulungs-Twin war im Picker auswählbar, aber jeder Daten-Zugriff darauf wurde von der RLS verweigert (live verifiziert: Twin-CCPs = 0 trotz vorhandener Daten). Ohne Fix wäre der Schulungs-Reiter eine leere, irreführende Hülle — die Kern-Funktion (Training im Twin) hätte nicht funktioniert.
- **Fix:** **Migration 0019** — `argus_exchange_person_code` um optionalen `p_scope`-Parameter (Default 'echt') erweitert; bei `p_scope='schulung'` wird die `schulungs_zwilling_id` server-seitig aufgelöst und ein twin-scoped JWT ausgestellt (`praesidium_id` = Twin; `usbnk`/`role`/`jti` unverändert; kein Twin → Fehler „Kein Schulungs-Zwilling…"). Feld-App: `exchangePersonCode(clean, scope)` reicht `p_scope` durch; `pickertab`-/`selectpraesidium`-Handler re-exchangen Person-Sitzungen nach der Bestätigung (offline-guarded); `refreshJwtIfNeeded()` nutzt `pickerMode()` als Scope. **RLS UNVERÄNDERT** — der Scope-Wechsel erfolgt rein über den server-ausgestellten JWT, nicht über Client-Claims.
- **Files modified:** `supabase/migrations/0019_phase51_twin_scope.sql` (neu), `index.html`
- **Verification:** Live + Browser: nach Wechsel zu Schulung flippt die JWT-`praesidium_id` auf den Twin, Twin-CCPs werden lesbar (5, war 0); Rückwärtskompatibilität (kein `p_scope` → echt) intakt; master-person-Login-Regression intakt; no-twin → Fehler. Alle Testdaten bereinigt. Migration 0019 ist **LIVE**.
- **Committed in:** `584e606`
