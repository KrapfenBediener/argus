## Phase Boundary

Die **Feld-App (index.html) auf das Stufe-1-Identitätsmodell umstellen** — die in Phase 5
gebauten Server-Bausteine (`argus_exchange_person_code`, `schulungs_zwilling_id`, `audit_log`,
Aktions-Katalog) im Feld nutzbar machen. **Dies IST ein App-Release** (Versions-Bump, SW-Cache,
WHATS_NEW/UPDATE-Sheet) **und löst die Drehbuch-DAUERREGEL aus** — anders als Phase 5.

**IN SCOPE:**
- **Pro-Person-Login** im Feld: ein Freischalt-Feld, Auto-Erkennung (erst `argus_exchange_code`,
  dann `argus_exchange_person_code`). Person-Token → Sitzung trägt USBNK + Rolle + Scope.
- **Echt/Schulung-Picker**: Top-Level Zwei-Reiter (Echtbetrieb/Schulung), Default Echtbetrieb,
  unverkennbarer SCHULUNG-Banner. Person-Token = eigenes Präsidium **+** Schulungs-Twin
  (`schulungs_zwilling_id`).
- **Personenscharfe Feld-Audit-Verdrahtung**: **server-seitige Trigger** auf patients/ccps
  schreiben mit `argus_usbnk()` ins `audit_log` (D-06-Katalog). Neue Migration (~0018).
- **`'normal'`-Rolle entsperren** (Einzel-Ausgabe über die Leitungs-Seite) — die 0017-Sperre
  rückgängig für individuelle Ausgabe (pro Präsidium, geringe Menge). Migration-Teil.
- App-Release + Trainings-Drehbuch (`TRAIN_LESSONS`) nachziehen.

**NICHT in dieser Phase (eigene Folgephasen):**
- **Massen-/Auto-Provisionierung** von Normalnutzer-Tokens → bleibt SSO/PTLS-gated (D-10).
- **Stufe 2 (SSO)** — IdP liefert USBNK transparent; Deployment/Echtbetrieb (PTLS/BITBW).
- FLZ-Lage-Ansicht auf der Leitungs-Seite (eigene Folgephase / Phase 6).

<decisions>
## Implementation Decisions (locked)

### D — Rollout & Scope
- **D5.1-01:** 5.1 liefert die **Feld-App-Fähigkeit** (Person-Login + Picker + Audit) UND
  **entsperrt `'normal'` für Einzel-Ausgabe** (Leitungs-Seite, pro Präsidium, geringe Menge).
  PPF/Pilot sofort personenscharf nutzbar. **Massen-Provisionierung bleibt SSO-gated** (D-10).
  Sammel-/Gast-Codes bleiben gültig (Fremdkräfte-Fallback).

### A — Login-Koexistenz
- **D5.1-02:** **Ein Freischalt-Feld, Auto-Erkennung** — der bestehende Freischalt-Pfad
  (`doUnlock`/`exchangeCode`) probiert erst `argus_exchange_code` (Sammel/Gast/Master), dann
  `argus_exchange_person_code`. Person-Token → USBNK-Sitzung (Grundlage des personenscharfen
  Audits). Bestehende Geräte/Codes bleiben unverändert. Muster wie die Leitungs-Seiten-`doLogin`.

### B — Echt/Schulung-Picker
- **D5.1-03:** **Top-Level Zwei-Reiter** (Echtbetrieb/Schulung), **Default Echtbetrieb**,
  **unverkennbarer SCHULUNG-Banner** im Trainingsmodus (bestehenden schulung-Banner verstärken).
  Person-Token deckt eigenes Präsidium + Schulungs-Twin (`schulungs_zwilling_id`). Sammelcodes
  behalten das heutige Modell (ein Schulungs-Code → Schulungs-Präsidium direkt). MANV: Umschalten
  muss schnell sein, der aktive Modus IMMER unverkennbar (nie Training in einen Echteinsatz mischen).

### C — Feld-Audit-Verdrahtung
- **D5.1-04:** **Server-seitige Trigger** auf patients/ccps (lesen `argus_usbnk()` aus dem JWT)
  schreiben ins `audit_log` — manipulationssicher, client-unabhängig, lückenlos. Aktionen aus dem
  Phase-5-Katalog (D-06): patient_create/patient_cat_change/patient_ready/patient_checkout/
  patient_photo, ccp_open/ccp_close/ccp_merge. Neue Migration (~0018), idempotent, via Management API.

### Claude's Discretion (Implementierung — Researcher/Planner)
- Trigger-Mechanik: Aktions-Typ aus NEW/OLD-Spaltendiff ableiten (create vs. cat_change vs. ready
  vs. checkout vs. photo); AFTER INSERT/UPDATE auf patients, AFTER auf ccps. `set search_path`.
- `'normal'`-Entsperrung: `argus_master_issue_person`/`argus_master_role_change_person`-Whitelist
  wieder um `'normal'` erweitern (0017 hatte es gesperrt) — sauber dokumentieren (5.1-Freigabe).
- Login-Auto-Erkennung im Feld: Reihenfolge/Fehlerbehandlung wie Leitungs-Seite; Geräte-
  Freischalt-Liste (`argus_unlocked`) vs. Person-Scope sauber zusammenführen.
- Picker-State-Persistenz (welcher Reiter aktiv), Realtime/CCP-Listen je Scope.
</decisions>

<specifics>
## Specific Ideas / Vollständigkeits-Punkte (im Plan berücksichtigen)

1. **Feldtauglichkeit zuerst:** Der Picker + Login dürfen die unter Stress bewährte Einfachheit
   NICHT verkomplizieren. Großflächig, einhändig, eindeutig. Der häufige Fall (ein einzelner
   Echt-Einsatz) bleibt so schlicht wie heute — der Schulungs-Reiter ist die Ausnahme.
2. **Schulung NIE versehentlich:** Der SCHULUNG-Modus muss permanent und unübersehbar markiert
   sein; ein Wechsel Echt↔Schulung mit klarer Bestätigung, damit kein Trainingseintrag in einen
   echten MANV gerät (und umgekehrt). Übungsdaten bleiben getrennt (eigenes Schulungs-Präsidium/Twin).
3. **Offline/Local-first bleibt:** Person-Login darf das Offline-Weiterarbeiten nicht brechen
   (JWT lokal + stille Verlängerung wie bisher; Picker-Scope offline gemerkt).
4. **Audit-Volumen/Trigger-Entscheid (offen für Researcher):** Loggen die Trigger Feld-Aktionen
   AUCH bei Stufe-0-Sitzungen (usbnk=null), oder nur bei vorhandener USBNK? Abwägung Vollständigkeit
   (§ 73 Verlaufsprotokoll) vs. Volumen im MANV + Null-Actor-Rauschen. Empfehlung tendiert zu
   „loggen mit usbnk=argus_usbnk() (null bei Stufe 0)", filterbar — Researcher/Owner bestätigen.
5. **`'normal'`-Person-Token → Feld-Zugriff:** `argus_exchange_person_code` setzt für role='normal'
   `praesidium_id` (Patientenzugriff via RLS) — das ist gewollt (Feld-Erfassung). Sicherstellen,
   dass CR-02 unberührt bleibt (Person-Codes weiterhin NUR über den Person-Exchange).
6. **Release-Hygiene:** APP_VERSION-Bump (vorauss. v0.32.0), SW-Cache-Bump (v59), CHANGELOG,
   WHATS_NEW, ggf. `docs/UPDATE_v0.32.html` (visuelles Sheet, [[release-convention]]). version.json.
7. **Trainings-Drehbuch (`TRAIN_LESSONS`) anpassen** — DAUERREGEL: Login/Picker-Änderungen spiegeln.
8. **tacSTART NICHT anfassen** ([[mdr-tacstart-accepted]]). Keine Änderung der Sichtungslogik.
9. **Migration(en) ~0018**: Feld-Audit-Trigger + `'normal'`-Entsperrung; idempotent; Management API
   + ephemerer PAT (Checkpoint); REST-/Trigger-Funktionstests.
10. **Live-Verifikation**: Browser-Roundtrip (Person-Login im Feld, Echt/Schulung-Wechsel, eine
    Patienten-Aktion → audit_log-Eintrag mit USBNK) + iPhone-Update-Test (Release).
</specifics>
