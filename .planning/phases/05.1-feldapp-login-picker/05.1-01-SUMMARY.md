## Decisions Made

- **Vital-only update → kein Eintrag (D-06):** Reine Vitalwert-Änderungen (vit-jsonb) produzieren KEINEN audit_log-Eintrag. D-06 definiert explizit, dass keine Einzelfeld-Diffs protokolliert werden — confirmed by live test (vital-only update = 0 new rows).
- **Eintrag auch bei usbnk=null:** §73-Vollständigkeit verlangt lückenlose Protokollierung; null-USBNK (Stufe-0-Session) ist ein auditables Faktum, das später filterbar bleibt (nicht verworfen werden darf).
- **Genau 1 Eintrag pro UPDATE:** Prioritäts-Kette (photo > checkout > ready > cat_change / ccp_close > ccp_merge) stellt sicher, dass ein einziger DML-Aufruf nie zwei audit_log-Zeilen erzeugt.
- **praesidium_id via ccps JOIN:** patients hat keine eigene praesidium_id-Spalte; der Trigger löst über `SELECT praesidium_id FROM ccps WHERE id = NEW.ccp_id` auf — konsistent, auch wenn die praesidium_id nachträglich an der ccps-Row gesetzt wird.
