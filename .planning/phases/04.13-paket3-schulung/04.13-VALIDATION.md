# Phase 04.13 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.
> Quelle: 04.13-RESEARCH.md, Abschnitt „Validation Architecture".

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Kein npm-Framework — projektüblich JSC (JavaScriptCore via `osascript -l JavaScript`) + REST-Tests gegen die Live-Instanz (Supabase Management API + ephemerer PAT) |
| **Config file** | none — Wave 0 entfällt (keine Test-Dateien nötig) |
| **Quick run command** | Script-Blöcke extrahieren (python3) → `new Function(...)`-Syntax-Check via osascript |
| **Full suite command** | JSC-Syntax (index.html + Leitungs-Seite) + grep-Gates (Flag-Gate, D-06, SW v51) + Precache-Konsistenz + REST-Tests Migration 0011 (2× anwenden = Idempotenz; RPC-Positiv-/Negativfälle) |
| **Estimated runtime** | ~60–120 s (REST-Tests inklusive) |

---

## Sampling Rate

- **After every task commit:** JSC-Syntax-Check der geänderten Datei(en).
- **After each plan:** Full suite (grep-Gates + REST-Tests des jeweiligen Plans).
- **Before phase close:** kompletter Gate-Lauf + Live-Smoke (GitHub Pages: version.json, Marker-Grep).

| Req | Behavior | Test Type | Automated Command / Check |
