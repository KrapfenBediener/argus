### Locked Decisions

**Reset-Design (Tombstone statt DELETE)**
- Neuer RPC `argus_schulung_reset(p_praesidium_id)` (Migration 0011, security definer): NUR für Präsidien mit `schulung=true` (sonst Fehler); Berechtigung Master ODER eigenes Präsidium (Trainer vor Ort resettet selbst). Je offenem CCP: patients+checklists löschen, Row **tombstonen** (closed_at=now, ort='', master_medic='', join_token=null) → Offline-Geräte bereinigen sich über die VORHANDENE checkClosedEinsatz/handleRemoteClose-Mechanik beim Reconnect. Akzeptiertes Restrisiko: ein Gerät, das >7 Tage offline in einer Schulung war, verpasst den Tombstone und behält lokalen Übungsmüll bis zum manuellen Aufräumen — dokumentieren, kein Blocker.
- **Kein purge_log-/governance_log-Eintrag** für Schulungs-Resets.
- Demo-Neubefüllung bleibt CLIENTSEITIG in der Feld-App (genDemoRows existiert dort); der Reset-Knopf bleibt in der Feld-App (Trainer vor Ort). Gate des Knopfs: `_praesidiumSchulung`-Flag statt Namens-Vergleich ('Schulungsumgebung').

### F2: Tombstone-Mechanik — Client und Server

**Clientseitige Tombstone-Erkennung (index.html, Zeilen 1300–1360):**

```js
// isCcpClosedRow: Tombstone = join_token null UND ort leer UND master_medic leer
function isCcpClosedRow(row){
  if(!row) return false;
  if(row.closed_at) return true;
  return ('join_token' in row) && !row.join_token && !(row.ort||'') && !(row.master_medic||'');
}
```

**Wichtig für den Reset-RPC:** Ein Schulungs-Reset muss dieselbe Tombstone-Signatur erzeugen: `closed_at=now()`, `ort=''`, `master_medic=''`, `join_token=null`. Dann erkennen Offline-Geräte den Reset identisch zum regulären Einsatz-Abschluss und rufen `handleRemoteClose()` auf.

**Serverseite (Migration 0002, argus_run_purge):** Der Purge setzt das Tombstone-Muster:
```sql
update public.ccps set ort = '', master_medic = '', join_token = null where id = r.id;
```

**Tombstone-Hygiene im Reset-RPC:** Schulungs-Tombstones (ccps mit `closed_at` gesetzt + Schulungs-Präsidium) müssen nach 7 Tagen hart gelöscht werden (DELETE on ccps). Die Purge-Guard-Logik aus argus_run_purge (schreibt in purge_log) **nicht kopieren** — kein Log für Schulungs-Resets (CONTEXT-Entscheid).

**Erscheinen Tombstones in `argus_governance_einsaetze`?** Filter in 0003/0009:
```sql
where c.closed_at is not null
  and (exists(patients) or exists(checklists) or ort<>'' or master_medic<>'' or join_token is not null)
```
Ein vollständiger Tombstone (ort='', master_medic='', join_token=null, keine Patienten/Checklisten nach dem Reset) **erscheint nicht** in der Governance-Liste. Damit kein Schulungs-Protokoll-Spam auf der Leitungs-Seite.

### F3: RPC-/Migrationsmuster des Projekts

**Aus 0008 (argus_claim_nums) und 0009 (argus_mark_export) destilliert:**

```sql
create or replace function public.argus_NEUER_RPC(...)
  returns jsonb
  language plpgsql
  security definer
  set search_path to 'public'
as $function$
declare
  v_now bigint := (extract(epoch from now())*1000)::bigint;
  v_xxx record;
begin
  -- Berechtigungs-Gate:
  if not public.argus_is_master()
     and ( public.argus_praesidium_id() is null
           or v_xxx.praesidium_id is distinct from public.argus_praesidium_id() ) then
    return jsonb_build_object('error', 'Keine Berechtigung');
  end if;
  -- Inhaltsprüfungen:
  if ... then return jsonb_build_object('error', '...'); end if;
  -- Hauptlogik
  ...
  return jsonb_build_object('key', value);
end;
$function$;
grant execute on function public.argus_NEUER_RPC(...) to anon;
comment on function public.argus_NEUER_RPC(...) is '...';
```

**Besonderheit `argus_schulung_reset`:** Berechtigung ist ENTWEDER master ODER eigenes Präsidium (= Trainer im Schulungs-Präsidium). Das Muster findet sich in `argus_close_einsatz` (0002/0003):
```sql
if not public.argus_is_master()
   and ( public.argus_praesidium_id() is null
         or v_ccp.praesidium_id is distinct from public.argus_praesidium_id() ) then
  return jsonb_build_object('error', 'Keine Berechtigung');
end if;
```

**Besonderheit `argus_provision_schulung`:** master-only (strenger), kein Präsidiums-Gate nötig:
```sql
if not public.argus_is_master() then
  raise exception 'Nur mit MasterUser-Token';
end if;
```
Muster analog `argus_governance_einsaetze`, `argus_mark_export`.

**Idempotenz:** Über `insert ... if not exists` (per Subquery oder `on conflict do nothing`).

**Zeitkonvention:** bigint in JS-Millisekunden für `closed_at` — `(extract(epoch from now())*1000)::bigint`.

### F4: AT-MIST-Druckansicht

**Feld-App (index.html, Zeilen 2198–2267):**

`exportPrintCard(p)` erzeugt eine `.card` mit AT-MIST-Reihenfolge:

| Buchstabe | Label | Felder |
|-----------|-------|--------|
| A | Alter / Geschlecht | `p.age`, `p.gender` |
| T | Zeiten | `p.tqStart` (fmtDur), `p.created` (ageStr) |
| M | Mechanismus | `p.moi` |
| I | Verletzungen | `p.inj[]`, `p.injury` |
| S | Befund / Vitalwerte | `p.vit` (WASB/AF/SpO₂/HF/RR/Schmerz), `p.allergies`, `p.vit.log[]` |
| T | Maßnahmen | `p.tqStart` (TQ-Timer), `TXG`-Gruppen |

Wichtig: **kein `<img>`-Tag**, kein Foto. Die Vorlage ist damit bereits sicher für die Leitungs-Seite (die `argus_governance_protokoll` Patienten ohne `photo` liefert, nur `has_photo`-Flag).

**Leitungs-Seite (docs/leitung-\<suffix\>.html):**

Aktuelles `vProtokollDetail` hat nur **einen** Druck-Knopf:
```js
'<button class="btn ghost" data-action="protoprint">🖨 Drucken</button>'
```
Handler: `if(a==='protoprint'){ window.print(); return; }` (Zeile 1105)

Das Raw-`window.print()` druckt die gesamte Protokoll-Ansicht (Tabelle + Checklisten + Governance-Log). Der neue Knopf „🖨 AT-MIST drucken" soll stattdessen eine dedizierte Karten-Ansicht öffnen (z. B. neues Overlay oder `<div id="atmist-print">` dynamisch einblenden) und dann `window.print()` auslösen.

**Druck-CSS (Leitungs-Seite, Zeilen 69–73):**
```css
@media print{
  .side,.topbar,.btn,.mh button{display:none!important}
  body{background:#fff}
  .layout{display:block}
}
```
Buttons (`.btn`) sind bereits aus dem Druck ausgeblendet. Ein neues Print-Overlay mit gesonderter Klasse (z. B. `.atmist-print-only`) muss per `@media print` sichtbar gemacht und alles andere ausgeblendet werden. Alternativ: Print-Scope per `@media print { body > *:not(#atmist-print) { display:none } }`.

**Verfügbare Felder aus `argus_governance_protokoll` (0003):**
```sql
(to_jsonb(p) - 'photo' - 'locked_by' - 'locked_at')
  || jsonb_build_object('has_photo', p.photo is not null)
```
Alle AT-MIST-relevanten Felder (num, ccp, cat, status, prio, name, age, gender, moi, injury, inj, vit, tx, tqStart, created, last_triage, allergies) sind vorhanden — `photo` ist entfernt, `has_photo`-Flag ergänzt. Die AT-MIST-Druckfunktion kann alle benötigten Werte direkt aus `_detail.data.patients` lesen.

**Unterschied Feld-App vs. Leitungs-Seite:**
- `nowMs()` — in der Leitungs-Seite bereits vorhanden: `function nowMs(){ return Date.now(); }`
- `fmtDur()` und `ageStr()` — in der Leitungs-Seite NICHT vorhanden (nur `fmtMs()`). Müssen portiert oder durch lokale Varianten ersetzt werden.
- `pno(p)` (Patienten-Nummer formatieren, z. B. „A-7") — NICHT in der Leitungs-Seite. Muss als Inline-Funktion eingebaut werden.
- `TXG` (Maßnahmen-Gruppen) — NICHT in der Leitungs-Seite. Müssen portiert werden (oder Maßnahmen als freier Text aus `p.tx`).
- `normalize(p)` — NICHT in der Leitungs-Seite. Defensive Null-Behandlung inline nötig.

## Common Pitfalls

### Pitfall 1: SW-Versionsnummer vergessen hochzählen
**Was geht schief:** CACHE_NAME bleibt auf v50 — iOS-Geräte bekommen das Update nicht zuverlässig.
**Ursache:** CONTEXT.md nennt fälschlicherweise v50 (schon verbraucht).
**Prävention:** CACHE_NAME = 'ccp-shell-**v51**' setzen; Precache-Konsistenz-Check läuft sowieso.

### Pitfall 2: Tombstone-Guard vergessen bei Schulungs-Tombstone-Hygiene
**Was geht schief:** `argus_schulung_reset` löscht Tombstones hart per `DELETE FROM ccps WHERE closed_at < now-7d AND praesidium_id = p_praesidium_id`. Wenn der Präsidiums-Check fehlt, könnte (bei zukünftiger Code-Rotation) ein falscher Präsidiums-Wert alle Tombstones löschen.
**Prävention:** `praesidium_id = p_praesidium_id` als Filter immer mitführen; Schulungs-Guard (`schulung=true`) ebenfalls prüfen.

### Pitfall 3: Tombstone erscheint in Governance-Liste
**Was geht schief:** Ein Reset-Tombstone mit noch vorhandenen Patienten/Checklisten (Race-Condition: Reset während Echtzeit-Sync) würde in `argus_governance_einsaetze` auftauchen.
**Prävention:** Der Reset-RPC löscht Patienten/Checklisten VOR dem Tombstonen (DELETE vor UPDATE). Reihenfolge in der RPC-Implementierung einhalten.

### Pitfall 4: `loadSchulDirty` nicht auf `_praesidiumSchulung` umgestellt
**Was geht schief:** `loadSchulDirty` bricht bei `_praesidiumName !== 'Schulungsumgebung'` vorzeitig ab (Zeile 1270) — in anderen Schulungs-Präsidien wird `_schulDirty` nie 0, der Reset-Knopf ist dauerhaft sichtbar.
**Prävention:** Zeile 1270 ebenfalls auf `!_praesidiumSchulung` umstellen (4. Umbaustelle).

### Pitfall 5: fmtDur / pno / TXG fehlen in der Leitungs-Seite
**Was geht schief:** AT-MIST-Druckfunktion referenziert Helper, die in index.html existieren, aber nicht in der Leitungs-Seite.
**Prävention:** Benötigte Helpers (fmtDur, ageStr, pno-Äquivalent, TXG-Daten) als minimale Inline-Implementierung in der Leitungs-Seite ergänzen.

### Pitfall 6: Schul-Tombstone-Hygiene löscht Tombstones, die ein Gerät noch nicht verarbeitet hat
**Was geht schief:** Gerät war >7 Tage offline, Tombstone wird hart gelöscht — beim Reconnect findet checkClosedEinsatz keinen CCP mehr (not found). `maybeSingle()` gibt `null` zurück, Handler erkennt es nicht als Abschluss.
**Prävention:** `checkClosedEinsatz` behandelt `not found` bereits korrekt (Zeile 1356: `if(r && r.data && isCcpClosedRow(r.data))`). Bei `null` wird kein handleRemoteClose getriggert — das Gerät bleibt auf dem alten Stand. Akzeptiertes Restrisiko (CONTEXT), in SELF-HOSTING.md dokumentieren.

## Open Questions

1. **Tombstone-Hygiene: Nur ccps löschen oder auch access_tokens des Schulungs-Präsidiums?**
   - Was wir wissen: Reset tombstont CCPs; Patienten/Checklisten werden gelöscht; Tombstones >7 Tage werden hart gelöscht.
   - Was unklar: Sollen mit dem Tombstone-Löschen auch verbrauchte Tokens des Schulungs-Präsidiums aufgeräumt werden?
   - Empfehlung: Nein — der Reset bezieht sich auf Übungsdaten (CCPs/Patienten), nicht auf Zugänge. Token-Hygiene läuft über argus_run_purge (6 Monate, Migration 0006). Kein Scope-Creep.

2. **`loadSchulDirty` nach Tombstone-Umbau: Zählt ein frisch tombstonter CCP als „verändert"?**
   - Was wir wissen: `loadSchulDirty` prüft: 6 offene CCPs A–F + Demo-Medics + Seed-Patienten.
   - Was unklar: Nach dem Tombstone-Reset wird `closed_at` gesetzt — die CCPs zählen dann als „geschlossen", nicht als „offen". Die loadSchulDirty-Prüfung würde `_schulDirty=1` setzen (< 6 offene CCPs).
   - Empfehlung: Das ist korrekt — nach dem Reset gibt es 0 offene CCPs, erst nach der clientseitigen Demo-Neubefüllung wieder 6. Im Übergang (RPC gelaufen, Demo noch nicht aufgebaut) ist _schulDirty=1, der Reset-Knopf bleibt kurz sichtbar. Kein Problem.
