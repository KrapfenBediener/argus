## Gruppen ↔ Spalten (Server, verbindlich, spiegelt FGROUPS des Clients)
- cat = cat, last_triage
- st = status, prio, ready
- vit = vit, pup_re, pup_li
- tx = tx
- tq = tq_start, tq_site
- stamm = name, age, gender, allergies, moi, injury, fr, notes, inj
- foto = photo
- del (Sondergruppe) = deleted_at, deleted_by, deleted_dev
- ack (Pseudo-Eintrag in fts, nur `t`) = Bestätigung von Konflikten
- Keine Gruppe (Identität/Laufzeit, Trigger lässt sie unangetastet): id, ccp_id, num, ccp, created, by, locked_by, locked_at; Sonderregeln für updated, fts, conf.

## fts-/conf-Format
- `fts = {"<gruppe>": {"t": <ms Server-Referenzzeit>, "d": <Gerätenummer>, "b": <Basis-Stempel>}, "ack": {"t": <ms>}}`
- `conf = [{"g": <gruppe>, "at": <ms Server>, "win": {"t","d"}, "lose": {"t","d","v"}}]` — v = Spaltenwerte der unterlegenen Gruppe als jsonb-Objekt; bei foto ohne v. Höchstens 20 Einträge.

## Grabstein-Inhalt (Server und Client identisch)
status 'verworfen', prio false, ready false, vit = Tabellen-Default aus 0000 (`{"af":"","hf":"","rr":"","avpu":"","pain":"","spo2":""}`), tx '{}', inj '[]', name/age/gender/allergies/moi/injury/fr/notes '', pup_re/pup_li '', tq_start null, tq_site null, photo null, conf '[]'. Unverändert: cat, last_triage, num, ccp, created, by, id, ccp_id.

## Kompatibilität
Alte Clients (≤ 0.33.22) senden weder fts noch deleted_* noch conf → Trigger-Fallback über `updated` je geänderter Gruppe; Grabsteine bleiben für sie unantastbar (sie senden nie fts.del); Grabsteine erscheinen dort nicht, weil status 'verworfen' von keiner Liste/Zählung (status 'active'/'gpa') erfasst wird.
